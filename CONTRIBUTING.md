# Contributing

1. Create a focused branch and keep unrelated changes out.
2. Put cross-platform domain behavior and tests in `packages/focus_core`.
3. Run formatting, analysis, tests, and the relevant platform build.
4. Update evidence and claim boundaries when changing defaults, behavior rationales, or product claims.
5. Complete the pull-request checklist. Do not mark physical-device checks complete without evidence tied to the commit.

User-visible claims must distinguish direct evidence, indirect inference, and unvalidated product heuristics. Accessibility, privacy, migration, and notification burden are release requirements rather than optional polish.
