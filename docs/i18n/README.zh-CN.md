# Random Cue Focus

简体中文 · [English](../../README.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português (Brasil)](README.pt-BR.md)

**回到你选择的任务，不让每次专注都变成接连不断的提醒。**

Random Cue Focus 是一款本地优先的 Flutter 辅助应用，面向希望在 iOS 或 Windows 上偶尔、按需提醒自己目标的人。`0.2.0` 版用稀疏、可跳过的目标检查替代原型中频繁且强制的“微休息”设计，默认静音且不发送通知。

本产品**参考研究证据设计，但未经临床验证**。它帮助你明确具体目标，偶尔检查是否仍在朝目标行动，并在分心后采用简单的“如果……那么……”恢复计划。它不宣称能够诊断注意力、提高生产力，也不宣称仅凭使用计时器就能改善学习效果。

<a id="when-it-may-fit"></a>

## 什么时候可能适合你

如果你希望轻量地重新关注自己的任务，而不想让每次专注都伴随一连串提醒，可以试用它。

- 开始前明确一个具体目标。
- 偶尔出现可选目标检查时，仍可继续工作。
- 察觉分心时，执行自己写下的恢复行动。
- 无需创建账号，即可查看本地专注历史。

你可以跳过检查，也可以在整次专注中关闭非必要检查。目的在于让自我检查可供使用，而不是强制打断；计时器或专注次数并不能证明它对你有帮助。

<a id="a-session-in-practice"></a>

## 一次实际使用流程

1. 设定目标，以及简单的“如果我分心，那么……”恢复行动。
2. 开始专注。全新安装默认关闭通知和前台声音。
3. 目标检查出现时，选择“仍在朝目标行动”“刚刚分心”或“跳过”。专注计时继续。
4. 按需暂停、休息或停止，然后可选填写进展与打断负担。
5. 查看保存在设备上的历史记录。

构建和运行说明见[开发](#develop)。本页尚未附设备实录；[发布状态](#release-status)区分了自动化检查与仍待完成的实机工作。

<a id="what-is-implemented"></a>

## 已实现的内容

- 一个共享且经过测试的 Dart 包，负责设置、专注模型、迁移、提示规划、自适应减负、自愿参加的交叉实验分配、本地结果汇总、按实验条件分层的数据就绪度分析、数据质量检查，以及保护隐私的研究导出。
- iOS 和 Windows 应用，具备专注／暂停／休息／停止状态、目标检查、本地历史和平台适配器。
- 全新安装默认值：专注 50 分钟、休息 10 分钟、检查间隔 12–18 分钟、响应窗口 20 秒、通知关闭、前台声音关闭。
- 明确的响应选项：“仍在朝目标行动”“刚刚分心”或“跳过”；检查期间专注计时继续。
- 可为整次专注关闭非必要目标检查；报告偏离任务绝不会使启发式规则提高打断频率。
- 目标、分心触发因素和下一步恢复行动均可由用户编辑，而非被视为通用脚本。
- 仅本地存储，无需账号、服务器或 API 密钥，不含广告 SDK 或远程分析。
- 专注结束后可选填写的进展与打断负担回答保存在本地；用户不回答时保持缺失。
- 实验性的本地交叉实验仅在明确同意后开放。它交替安排无检查与稀疏检查的专注，在开始暴露于相应条件之前持久化分配，不会自动上传，且可随时退出。
- CI 覆盖共享核心测试、两个应用的分析／测试、Windows 发布构建和 iOS 模拟器构建。

现有 `0.1.x` 版的设置与专注事件会迁移，而非被悄悄丢弃。模式版本 `6` 保留此前所有迁移、明确的研究加入状态和逐次专注分配，同时为新的研究专注增加实际目标检查启用状态、间隔与响应窗口快照。研究导出模式 v2 除去原始专注 ID、日期和自由文本，也移除了绝对分配时间戳。自适应节奏是确定性、可检查的启发式规则，并非机器学习模型；它至少等待三次专注和六次响应后才会改变间隔。

<a id="evidence-boundary"></a>

## 证据边界

设计优先考虑直接且相互印证的研究发现，并明确标注间接推断：

- 提醒可能干扰当前任务，因此外部通知与声音默认关闭。
- 短暂休息对活力／疲劳的益处比对认知表现的益处更一致，因此检查是可选的，且不承诺性能提升。
- 用户自行编写的执行意图与自我监测可能支持分心后的恢复，但现代对偏差更稳健的估计小于早期元分析估计；本应用及其 12–18 分钟默认间隔尚未经随机产品试验验证。
- 提取练习和间隔学习有更强的学习证据，但计时器本身不构成提取练习干预。

关于主张与功能的对应矩阵、局限、评估设计、模式契约及最低限度的证据有效学习闭环，请参阅[证据基础](../EVIDENCE_BASE.md)、[测量计划](../MEASUREMENT_PLAN.md)、[数据字典](../DATA_DICTIONARY.md)、[本地交叉实验协议](../LOCAL_CROSSOVER_PROTOCOL.md)和[实验性学习模式规范](../LEARNING_MODE_SPEC.md)。

<a id="common-questions"></a>

## 常见问题

**它与强制休息计时器有什么不同？** 目标检查不会停止专注计时。你可以回答、跳过，也可以为整次专注关闭非必要检查。休息仍是独立状态。

**如果我报告分心，它会更频繁地打断我吗？** 文档所述的减负启发式规则不会因偏离任务的自我报告而提高打断频率。它是确定性且可检查的规则，并非学习得到的注意力模型。

**为什么听不到提醒？** 全新安装默认关闭前台声音和外部通知。请主动检查设置，不要认为没有声音就表示专注失败。操作系统权限和后台行为也需要分平台验证。

**能从 Windows 安装 iPhone 应用吗？** 你可以在 Windows 编辑和测试 Dart 代码，但真正的 iPhone 构建／签名步骤需要 macOS 上的 Xcode。请参阅 [iOS 指南](../../apps/ios/README.md)。

**历史记录能证明我学得更多吗？** 不能。计时时长、完成情况和自我报告不是客观学习或生产力结果。可选结果问题未作答时保持缺失。

**我必须加入实验吗？** 不必。本地交叉实验要求明确同意，可以退出，也不会自动上传。使用前请参阅[协议](../LOCAL_CROSSOVER_PROTOCOL.md)。

<a id="develop"></a>

## 开发

安装当前稳定版 Flutter SDK 和目标平台所需工具。Windows 应用使用 Windows 开发主机，iOS 构建使用带有 Xcode 的 macOS。以下命令从仓库根目录开始；平台指南提供 [Windows](../../apps/windows/README.md) 和 [iOS](../../apps/ios/README.md) 的详细说明。

```powershell
cd packages\focus_core
dart pub get
dart analyze --fatal-infos
dart test

cd ..\..\apps\windows
flutter pub get
flutter analyze --fatal-infos
flutter test
flutter run -d windows
```

**首次成功操作：**运行本地应用构建，输入目标和恢复行动，开始专注，然后暂停并恢复。确认界面显示的专注状态发生变化。这只是基础本地操作演练，并不代表锁屏、睡眠／唤醒或原生通知行为已通过验收。

在 `apps/ios` 中运行对应的分析／测试命令。构建 iOS 需要 macOS 上的 Xcode；签名和实机通知验证需要 Apple 开发环境。

<a id="help-make-it-easier-to-use-and-verify"></a>

## 一起让它更易使用和验证

欢迎范围明确的贡献，尤其是无障碍支持、迁移安全、平台通知行为，以及更清晰的目标检查交互。

- 从 [CONTRIBUTING.md](../../CONTRIBUTING.md) 和你希望修改的模块测试开始。
- 共享行为保留在 `packages/focus_core`；平台特定行为保留在对应应用适配器中。
- 实机测试请使用 [DEVICE_ACCEPTANCE.md](../DEVICE_ACCEPTANCE.md)，并记录硬件、软件版本、提交、步骤和观察结果。
- 同时说明你执行过和无法执行的检查。

| 希望改进的内容 | 入口 | 应附验证 |
| --- | --- | --- |
| 提示规划与设置迁移 | `packages/focus_core` | 领域测试、迁移输入，以及未改变的隐私／默认值契约。 |
| iOS 专注界面或通知 | `apps/ios/lib`, `apps/ios/test` | 分析器／组件测试；单独列出实机检查。 |
| Windows 控制、持久化或托盘行为 | `apps/windows/lib`, `apps/windows/test` | 相关控制器／仓库测试，以及明确的平台证据。 |
| 产品说明 | `docs/EVIDENCE_BASE.md`, `docs/PRIVACY.md` | 与实际默认值以及证据／主张边界保持一致。 |

修改界面时，还应考虑重复操作、暂停／恢复、跳过检查和中断的专注。不要仅凭模拟器或模拟适配器就把实机验收项标记为完成。

较大改动请先开 [issue](https://github.com/son-gladyso/random-cue-focus/issues) 讨论。请勿将个人目标、历史或研究导出作为公开示例提交。贡献必须保留检查的可选性、隐私保护，以及已实现启发式规则与已证实益处之间的区别。
