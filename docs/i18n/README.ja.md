# Random Cue Focus

[简体中文](README.zh-CN.md) · [English](../../README.md) · 日本語 · [한국어](README.ko.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português (Brasil)](README.pt-BR.md) · [Русский](README.ru.md) · [繁體中文](README.zh-TW.md)

**「勉強しよう」を具体的な次の一歩に変え、気が散っても戻る場所を決めておく。**

Random Cue Focus は iOS と Windows 向けのローカルファーストの Flutter 学習補助アプリです。学習目標と小さな復帰行動を決め、タイマーを止めずに任意の目標確認を行えます。端末内の履歴と任意の進捗評価で学習過程を振り返ります。

教科書、問題集、復習ノートと併用し、学習の計画と自己モニタリングを支えます。`0.2.0` の確認は間隔を空け、スキップ可能で、初期設定では音も外部通知もありません。

<a id="learning-workflow"></a>

## 学習セッションでの使い方

「生物を勉強する」を「細胞分裂の節を読み、有糸分裂と減数分裂の違いを三つ書く」に変えます。「無関係なタブを開いたら、次の段落に戻り、比較を一つ書く」と決めます。任意の確認で目標に戻るか、スキップして読み続け、最後に進捗と中断の負担を記録します。

問題演習なら次の問題と再開する手順、復習なら自分の教材で思い出して説明する概念を指定します。読む、解く、想起する、答えを確かめるのは学習者です。編集可能な復帰計画は、自動指導ではありません。

<a id="when-it-may-fit"></a>

## どのようなときに向いているか

集中する時間を通知の連続にすることなく、自分のタスクに軽い負担で意識を戻したいときに使えます。

- 始める前に具体的な目標を決めます。
- ときどき表示される任意の目標確認中も、作業を続けられます。
- 気が散ったことに気づいたら、自分で書いた復帰行動を使います。
- アカウントを作らずに、端末内のセッション履歴を確認できます。

確認をスキップしたり、そのセッションでは必須でない確認を無効にしたりできます。狙いは中断を強制せずに自己確認の機会を用意することです。役に立つかどうかは、タイマーやセッション数では証明できません。

<a id="a-session-in-practice"></a>

## 実際のセッションの流れ

1. 目標と、簡単な「もし気が散ったら、〜する」という復帰行動を設定します。
2. 集中セッションを開始します。新規インストール時は通知とフォアグラウンド音が無効です。
3. 目標確認が表示されたら、「目標に取り組んでいる」「今、気が散った」「スキップ」から選びます。集中時間の計測は続きます。
4. 必要に応じて一時停止、休憩、終了を行い、その後、任意で進捗と中断の負担を記録します。
5. 端末に保存された履歴を確認します。

ビルドと実行の手順は[開発](#develop)を参照してください。実機での録画はまだ掲載していません。[リリース状況](#release-status)では、自動チェックと未完了の実機作業を区別しています。

<a id="what-is-implemented"></a>

## 実装済みの機能

- 設定、セッションモデル、移行、キュー計画、適応的な負担軽減、任意参加のクロスオーバー割り当て、ローカルな結果集計、条件別に層別化したデータ準備状況の評価、データ品質チェック、プライバシーを保護する研究用エクスポートを担う、共有のテスト済み Dart パッケージ。
- 集中／一時停止／休憩／終了の状態、目標確認、ローカル履歴、プラットフォームアダプターを備えた iOS および Windows アプリ。
- 新規インストール時の初期設定：集中 50 分、休憩 10 分、確認間隔 12〜18 分、回答時間 20 秒、通知オフ、フォアグラウンド音オフ。
- 明確な回答：「目標に取り組んでいる」「今、気が散った」「スキップ」。確認中も集中時間は進みます。
- 必須でない目標確認はセッション全体で無効にできます。タスクから外れたという報告によって、ヒューリスティックが中断頻度を増やすことはありません。
- 目標、気が散るきっかけ、次の復帰行動は、万人向けの定型文ではなくユーザー自身が編集できます。
- 保存はローカルのみで、アカウント、サーバー、API キー、広告 SDK、リモート分析はありません。
- セッション後の任意回答である進捗と中断負担はローカルに保存され、未回答なら欠測のままです。
- 実験的なローカルクロスオーバーは明示的な同意後にのみ利用できます。確認なしと低頻度の確認ありのセッションを交互に割り当て、条件への曝露前に割り当てを永続化し、自動アップロードは行わず、いつでも離脱できます。
- 共有コアのテスト、両アプリの解析／テスト、Windows リリースビルド、iOS シミュレータービルドを行う CI。

既存のバージョン `0.1.x` の設定とセッションイベントは、黙って破棄せず移行します。スキーマバージョン `6` は、過去のすべての移行、明示的な研究参加、セッションごとの割り当てを維持し、新しい研究セッションに実際の目標確認の有効状態、間隔、回答時間のスナップショットを追加します。研究用エクスポートスキーマ v2 は、生のセッション ID、日付、自由記述に加えて、割り当ての絶対タイムスタンプも削除します。適応的な間隔調整は決定的で検査可能なヒューリスティックであり、機械学習モデルではありません。間隔を変更する前に、少なくとも 3 セッションと 6 回の回答を待ちます。

## 学習過程を支える研究

| 研究・実験 | 知見 | 対応と限界 |
| --- | --- | --- |

| [Harkin et al. (2016)](https://doi.org/10.1037/bul0000025) | 138 件のランダム化研究、19,951 人：進捗確認を促す介入は目標達成を平均的に改善しました。 | 目標確認と振り返りの根拠。本アプリや成績への効果の試験ではありません。 |
| [Stothart et al. (2015)](https://doi.org/10.1037/xhp0000100) | 携帯を操作しなくても通知は注意課題を妨げました。 | 静かで任意の確認を支持。12–18 分が最適とは示していません。 |

**方法・過程の実験結果であり、本アプリの学習効果を測定した結果ではありません。** 製品の学習成果試験は未実施です。初期間隔は調整可能なヒューリスティックです。ローカル交差試験は確認条件と体験を比較する仕組みで、結果は報告していません。履歴や自己評価は学習得点ではありません。

想起練習や分散学習の研究はありますが、現アプリに想起問題、採点、教材の復習日程はありません。[学習モード](../LEARNING_MODE_SPEC.md)は仕様段階です。将来は同等の学習課題で遅延テスト、転移問題、中断負担を比較できますが、その評価は未実施です。

出典と主張の範囲は[エビデンス](../EVIDENCE_BASE.md)、既存の評価設計は[測定計画](../MEASUREMENT_PLAN.md)、[データ辞書](../DATA_DICTIONARY.md)、[交差試験プロトコル](../LOCAL_CROSSOVER_PROTOCOL.md)を参照してください。

## よくある質問

**強制休憩タイマーと何が違いますか？** 目標確認は集中時間を止めません。回答、スキップ、またはセッション全体の必須でない確認の無効化を選べます。休憩は独立した状態です。

**気が散ったと報告すると、中断が増えますか？** 文書化された負担軽減ヒューリスティックは、タスクから外れたという自己報告後に中断頻度を増やしません。決定的で検査可能な仕組みであり、学習された注意モデルではありません。

**なぜリマインダーの音が聞こえませんか？** 新規インストール時はフォアグラウンド音と外部通知が無効です。静かなセッションを失敗と考える前に、意図的に設定を確認してください。OS の権限とバックグラウンド動作も、プラットフォームごとの検証が必要です。

**Windows から iPhone アプリをインストールできますか？** Dart コードの編集とテストは可能ですが、実際の iPhone 向けビルド／署名には macOS 上の Xcode が必要です。[iOS ガイド](../../apps/ios/README.md)を参照してください。

**履歴は学習量が増えた証拠ですか？** いいえ。タイマーの時間、完了、自分の申告は、客観的な学習成果や生産性の結果ではありません。任意の結果質問は、回答しなければ欠測のままです。

**実験への参加は必須ですか？** いいえ。ローカルクロスオーバーには明示的な同意が必要で、離脱でき、自動アップロードもありません。利用前に[プロトコル](../LOCAL_CROSSOVER_PROTOCOL.md)を確認してください。

<a id="develop"></a>

## 開発

現在の安定版 Flutter SDK と対象プラットフォーム用のツールをインストールしてください。Windows アプリには Windows の開発環境、iOS ビルドには Xcode のある macOS を使います。以下のコマンドはリポジトリのルートから開始します。詳しくは [Windows](../../apps/windows/README.md) と [iOS](../../apps/ios/README.md) のプラットフォーム別ガイドを参照してください。

```powershell
cd packages\focus_core
dart pub get
dart analyze --fatal-infos
dart test

cd ..\..\apps\windows
flutter pub get
flutter analyze --fatal-infos
flutter test
flutter run -d windows
```

**最初の成功確認：**ローカルでビルドしたアプリを実行し、目標と復帰行動を入力してセッションを開始し、一時停止して再開します。表示されるセッション状態が変化することを確認してください。これは基本的なローカル操作確認であり、ロック画面、スリープ／復帰、ネイティブ通知の動作の受け入れ確認ではありません。

`apps/ios` 内で同等の解析／テストコマンドを実行します。iOS のビルドには macOS 上の Xcode が必要で、署名と実機の通知検証には Apple の開発環境が必要です。

<a id="help-make-it-easier-to-use-and-verify"></a>

## 使いやすさと検証しやすさの改善に参加する

対象を絞った貢献を歓迎します。特にアクセシビリティ、移行の安全性、プラットフォームの通知動作、より分かりやすい目標確認の操作が重要です。

- [CONTRIBUTING.md](../../CONTRIBUTING.md) と、変更したいモジュールのテストから始めてください。
- 共通動作は `packages/focus_core` に、プラットフォーム固有の動作は各アプリのアダプターに置いてください。
- 実機テストでは [DEVICE_ACCEPTANCE.md](../DEVICE_ACCEPTANCE.md) を使い、ハードウェア、ソフトウェアのバージョン、コミット、手順、観測結果を記録してください。
- 実行したチェックと、実行できなかったチェックの両方を記述してください。

| 改善したい対象 | 入口 | 添える検証 |
| --- | --- | --- |
| キュー計画と設定の移行 | `packages/focus_core` | ドメインテスト、移行入力、プライバシー／初期設定の契約が不変であること。 |
| iOS セッション UI または通知 | `apps/ios/lib`, `apps/ios/test` | 解析／ウィジェットテスト。実機チェックは別途明記。 |
| Windows 制御、永続化、トレイ動作 | `apps/windows/lib`, `apps/windows/test` | 関連するコントローラー／リポジトリテストと明確なプラットフォームの証拠。 |
| 製品説明 | `docs/EVIDENCE_BASE.md`, `docs/PRIVACY.md` | 実際の初期設定、エビデンスと主張の境界との一貫性。 |

インターフェースを変更する際は、繰り返し操作、一時停止／再開、確認のスキップ、中断されたセッションも考慮してください。シミュレーターやモックアダプターだけを根拠に、実機のゲートを完了扱いにしてはいけません。

大きな変更は [issue](https://github.com/son-gladyso/random-cue-focus/issues) を開いて相談してください。個人的な目標、履歴、研究用エクスポートを公開例として提出しないでください。貢献では、確認の任意性、プライバシー、実装済みのヒューリスティックと実証された利益の区別を維持する必要があります。
