# Random Cue Focus

[简体中文](README.zh-CN.md) · [English](../../README.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português (Brasil)](README.pt-BR.md) · [Русский](README.ru.md) · [繁體中文](README.zh-TW.md)

**把「我要學習」變成具體的下一步，分心後也知道從哪裡繼續。**

Random Cue Focus 是面向 iOS 和 Windows 的本機優先 Flutter 學習輔助應用程式。明確本次學習目標，寫下一個小的回復行動，在不中斷計時的情況下偶爾、自願檢查是否仍在朝目標行動；本機歷史與可選進展自評幫助你回顧學習過程。

它可以配合課本、習題和複習筆記使用，支持學習前的規劃與學習中的自我監測。`0.2.0` 版採用稀疏、可略過的目標檢查，預設靜音且不發送通知。

<a id="learning-workflow"></a>

## 怎樣用它完成一次學習

把「學一會兒生物」改成「讀完細胞分裂這一節，寫出有絲分裂與減數分裂的三個差異」。再寫下「如果我開啟無關網頁，那麼就回到下一段，先寫一個比較點」。出現可選檢查時，重新對照目標，或略過檢查繼續閱讀；結束後記錄完成了什麼、檢查是否造成負擔。

做題時可以明確下一道題和恢復解題的步驟；複習時可以指定要用自己的材料回憶、解釋的概念。應用程式提供目標與計畫的支架，閱讀、解題、回憶和核對由你完成。回復計畫可編輯，並非自動指導介入。

<a id="when-it-may-fit"></a>

## 什麼時候可能適合你

當你希望用輕量方式重新連結自己的任務，又不想讓每次專注都充滿提醒時，可以試用。

- 開始前說明一個具體目標。
- 偶爾出現可選目標檢查時，仍可繼續工作。
- 察覺分心時，使用自己寫下的回復行動。
- 不必建立帳號，即可查看本機專注歷史。

你可以略過檢查，或在整次專注關閉非必要檢查。目的是讓自我檢查可供使用，而非強制打斷；計時器或專注次數並不能證明它對你有幫助。

<a id="a-session-in-practice"></a>

## 一次實際使用流程

1. 設定目標及簡單的「如果我分心，那麼……」回復行動。
2. 開始專注。全新安裝預設關閉通知與前景音效。
3. 目標檢查出現時，選擇「仍在朝目標行動」、「剛剛分心」或「略過」。專注計時繼續。
4. 依需要暫停、休息或停止，再選擇是否記錄進展與打斷負擔。
5. 查看儲存在裝置上的歷史。

建置與執行說明見[開發](#develop)。本頁尚未附裝置實錄；[發布狀態](#release-status)區分自動化檢查與仍待完成的實機工作。

<a id="what-is-implemented"></a>

## 已實作內容

- 一個共用且經測試的 Dart 套件，負責設定、專注模型、遷移、提示規劃、自適應減負、自願參加的交叉實驗分派、本機結果摘要、依實驗條件分層的資料就緒度分析、資料品質檢查，以及保護隱私的研究匯出。
- iOS 與 Windows 應用程式，具有專注／暫停／休息／停止狀態、目標檢查、本機歷史及平台介接層。
- 全新安裝預設：專注 50 分鐘、休息 10 分鐘、檢查間隔 12–18 分鐘、回應視窗 20 秒、通知關閉、前景音效關閉。
- 明確的回應選項：「仍在朝目標行動」、「剛剛分心」或「略過」；檢查期間專注計時繼續。
- 可為整次專注停用非必要目標檢查；回報偏離任務不會讓啟發式規則提高打斷頻率。
- 目標、分心觸發因素及下一步回復行動都由使用者編輯，而非視為通用腳本。
- 僅在本機儲存，無帳號、伺服器、API 金鑰、廣告 SDK 或遠端分析。
- 專注結束後的可選進展與打斷負擔回答儲存在本機；未作答時維持缺值。
- 實驗性本機交叉實驗僅在明確同意後開放。它交替安排無檢查與稀疏檢查的專注，在開始接觸相應條件前持久化分派，不會自動上傳，且可隨時退出。
- CI 涵蓋共用核心測試、兩個應用程式的分析／測試、Windows 發布建置及 iOS 模擬器建置。

既有 `0.1.x` 設定與專注事件會遷移，而非默默丟棄。綱要版本 `6` 保留所有先前遷移、明確研究加入狀態與逐次專注分派，並為新研究專注加入實際目標檢查啟用狀態、間隔與回應視窗快照。研究匯出綱要 v2 除了原始專注 ID、日期及自由文字，也移除絕對分派時間戳記。自適應節奏是確定性、可檢視的啟發式規則，不是機器學習模型；至少等待三次專注及六次回應後才改變間隔。

## 這些設計的研究依據

| 研究與實驗 | 發現 | 對應環節與邊界 |
| --- | --- | --- |
| [Gollwitzer & Sheeran (2006)](https://doi.org/10.1016/S0065-2601(06)38002-1) | if–then 計畫統合分析發現平均目標達成收益，但情境差異大，現代偏誤穩健估計較小。 | 支持自寫回復計畫；不能推出隨機提醒能提高學習效果。 |
| [Harkin et al. (2016)](https://doi.org/10.1037/bul0000025) | 138 項隨機研究、19,951 人：促進進展監測的介入平均改善目標達成。 | 支持目標檢查與回顧；並非本應用程式或成績提升實驗。 |
| [Stothart et al. (2015)](https://doi.org/10.1037/xhp0000100) | 即使不操作手機，收到通知也會干擾注意力作業。 | 支持安靜、可略過的檢查；不證明 12–18 分鐘是最佳間隔。 |

**以上是相關方法與過程的實驗證據，不是本軟體已測得學習收益的證據。** 尚未開展產品學習效果實驗；預設間隔是可調整的啟發式設定。本機交叉工具用於比較檢查條件與體驗，目前沒有結果可報告。歷史與自評用於反思，不是學習成績。

提取練習與間隔學習有研究支持，但目前應用程式不提供回憶題、答案批改或內容複習排程；[學習模式](../LEARNING_MODE_SPEC.md)仍是規格文件。未來可在配對學習任務中比較延遲測驗、遷移題與打斷負擔，這項評估尚未實施。

完整出處與主張邊界見[證據基礎](../EVIDENCE_BASE.md)；現有評估契約見[測量計畫](../MEASUREMENT_PLAN.md)、[資料字典](../DATA_DICTIONARY.md)和[本機交叉實驗協定](../LOCAL_CROSSOVER_PROTOCOL.md)。

<a id="common-questions"></a>

## 常見問題

**它與強制休息計時器有何不同？**目標檢查不停止專注計時。你可以回答、略過，或在整次專注停用非必要檢查。休息仍是獨立狀態。

**如果回報分心，它會更頻繁打斷我嗎？**文件所述的減負啟發式規則，不會因偏離任務的自我回報提高打斷頻率。它是確定性且可檢視的規則，不是學習而得的注意力模型。

**為什麼聽不到提醒？**全新安裝預設關閉前景音效與外部通知。請主動檢查設定，不要假設安靜的專注就是失敗。作業系統權限與背景行為也需要依平台驗證。

**能從 Windows 安裝 iPhone 應用程式嗎？**可在 Windows 編輯及測試 Dart 程式碼，但實際 iPhone 建置／簽署需要 macOS 上的 Xcode。請參閱 [iOS 指南](../../apps/ios/README.md)。

**歷史能證明我學得更多嗎？**不能。計時長度、完成情況及自我回報不是客觀學習或生產力結果。可選結果問題未作答時維持缺值。

**我必須加入實驗嗎？**不必。本機交叉實驗要求明確同意，可退出且不會自動上傳。使用前請閱讀[協定](../LOCAL_CROSSOVER_PROTOCOL.md)。

<a id="develop"></a>

## 開發

安裝目前穩定版 Flutter SDK 及目標平台工具。Windows 應用程式使用 Windows 開發主機，iOS 建置使用搭配 Xcode 的 macOS。以下指令從儲存庫根目錄開始；[Windows](../../apps/windows/README.md) 與 [iOS](../../apps/ios/README.md) 平台指南提供詳細資訊。

```powershell
cd packages\focus_core
dart pub get
dart analyze --fatal-infos
dart test

cd ..\..\apps\windows
flutter pub get
flutter analyze --fatal-infos
flutter test
flutter run -d windows
```

**首次成功操作：**執行本機應用程式建置，輸入目標與回復行動，開始專注，再暫停及繼續。確認顯示的專注狀態改變。這只是基本本機操作演練，不代表鎖定畫面、睡眠／喚醒或原生通知行為已驗收。

在 `apps/ios` 執行對應分析／測試指令。iOS 建置需要 macOS 上的 Xcode；簽署及實機通知驗證需要 Apple 開發環境。

<a id="help-make-it-easier-to-use-and-verify"></a>

## 一起讓它更容易使用與驗證

歡迎聚焦的貢獻，尤其是無障礙支援、遷移安全、平台通知行為與更清楚的目標檢查互動。

- 從 [CONTRIBUTING.md](../../CONTRIBUTING.md) 及欲修改模組的測試開始。
- 共用行為留在 `packages/focus_core`；平台特有行為留在其應用程式介接層。
- 實機測試使用 [DEVICE_ACCEPTANCE.md](../DEVICE_ACCEPTANCE.md)，記錄硬體、軟體版本、提交、步驟與觀察結果。
- 同時說明已執行及無法執行的檢查。

| 希望改進的內容 | 入口 | 應附驗證 |
| --- | --- | --- |
| 提示規劃與設定遷移 | `packages/focus_core` | 領域測試、遷移輸入與未改變的隱私／預設值契約。 |
| iOS 專注介面或通知 | `apps/ios/lib`, `apps/ios/test` | 分析器／元件測試；實機檢查另行列出。 |
| Windows 控制、持久化或系統匣行為 | `apps/windows/lib`, `apps/windows/test` | 相關控制器／儲存庫測試與明確平台證據。 |
| 產品說明 | `docs/EVIDENCE_BASE.md`, `docs/PRIVACY.md` | 與實際預設值及證據／主張邊界一致。 |

修改介面時，也要考慮重複操作、暫停／繼續、略過檢查及中斷的專注。不要僅憑模擬器或模擬介接層就將實機驗收標記為完成。

較大變更請先提出 [issue](https://github.com/son-gladyso/random-cue-focus/issues) 討論。請勿將個人目標、歷史或研究匯出當作公開範例提交。貢獻必須保留檢查的可選性、隱私，以及已實作啟發式規則和已證實益處之間的區別。
