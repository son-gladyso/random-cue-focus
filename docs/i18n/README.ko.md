# Random Cue Focus

[简体中文](README.zh-CN.md) · [English](../../README.md) · [日本語](README.ja.md) · 한국어 · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português (Brasil)](README.pt-BR.md) · [Русский](README.ru.md) · [繁體中文](README.zh-TW.md)

**집중할 때마다 알림이 쏟아지지 않도록, 스스로 선택한 작업으로 돌아오세요.**

Random Cue Focus는 iOS 또는 Windows에서 자신의 목표를 가끔 선택적으로 확인하고 싶은 사람을 위한 로컬 우선 Flutter 보조 앱입니다. `0.2.0` 버전은 프로토타입의 빈번하고 강제적인 “짧은 휴식” 방식을 간격이 넓고 건너뛸 수 있는 목표 확인으로 바꾸었습니다. 기본적으로 소리도 알림도 없습니다.

이 제품은 **연구 근거를 참고했지만 임상적으로 검증되지는 않았습니다**. 구체적인 목표를 정하고, 여전히 그 목표에 따라 행동하는지 가끔 확인하며, 주의가 흐트러진 뒤 간단한 “만약…그러면…” 복귀 계획을 사용하도록 돕습니다. 주의력을 진단하거나, 생산성을 높이거나, 타이머 사용만으로 학습 효과를 개선한다고 주장하지 않습니다.

<a id="when-it-may-fit"></a>

## 어떤 때 적합할까요

집중 시간을 끊임없는 알림으로 채우지 않으면서, 부담 없이 자신의 작업에 다시 주의를 돌리고 싶을 때 사용하세요.

- 시작하기 전에 구체적인 목표를 정합니다.
- 가끔 표시되는 선택적 목표 확인 중에도 작업을 계속합니다.
- 산만해졌음을 알아차리면 직접 작성한 복귀 행동을 사용합니다.
- 계정을 만들지 않고 로컬 세션 기록을 확인합니다.

확인을 건너뛰거나 해당 세션의 필수적이지 않은 확인을 끌 수 있습니다. 목적은 중단을 강요하지 않고 자기 점검 기회를 제공하는 것입니다. 타이머나 세션 수만으로 도움이 되는지는 입증할 수 없습니다.

<a id="a-session-in-practice"></a>

## 실제 세션 진행 방법

1. 목표와 간단한 “만약 주의가 흐트러지면…” 복귀 행동을 설정합니다.
2. 집중 세션을 시작합니다. 새로 설치하면 알림과 포그라운드 소리가 꺼져 있습니다.
3. 목표 확인이 나타나면 “계속 목표에 집중 중”, “방금 산만해짐”, “건너뛰기” 중 하나를 선택합니다. 집중 시간은 계속 흐릅니다.
4. 필요에 따라 일시 정지, 휴식, 중지를 선택하고, 원하면 진행 상황과 방해 부담을 기록합니다.
5. 기기에 저장된 기록을 살펴봅니다.

빌드와 실행 방법은 [개발](#develop)에 있습니다. 아직 기기 녹화는 제공하지 않습니다. [출시 상태](#release-status)에서는 자동화된 검사와 아직 남아 있는 실기기 작업을 구분합니다.

<a id="what-is-implemented"></a>

## 구현된 기능

- 설정, 세션 모델, 마이그레이션, 신호 계획, 적응형 부담 감소, 자발적 교차 실험 배정, 로컬 결과 요약, 조건별로 층화한 데이터 준비도 분석, 데이터 품질 검사, 개인정보를 보호하는 연구용 내보내기를 위한 테스트된 공통 Dart 패키지.
- 집중/일시 정지/휴식/중지 상태, 목표 확인, 로컬 기록, 플랫폼 어댑터를 갖춘 iOS 및 Windows 앱.
- 새 설치 기본값: 집중 50분, 휴식 10분, 확인 간격 12~18분, 응답 시간 20초, 알림 끔, 포그라운드 소리 끔.
- 명확한 응답: “계속 목표에 집중 중”, “방금 산만해짐”, “건너뛰기”. 확인 중에도 집중 시간은 계속 흐릅니다.
- 필수적이지 않은 목표 확인을 세션 전체에서 끌 수 있습니다. 작업에서 벗어났다는 보고 때문에 휴리스틱이 방해 빈도를 높이지는 않습니다.
- 목표, 산만함의 유발 요인, 다음 복귀 행동은 보편적인 대본으로 취급되지 않으며 사용자가 편집할 수 있습니다.
- 로컬 전용 저장소를 사용하며 계정, 서버, API 키, 광고 SDK, 원격 분석이 없습니다.
- 세션 후 선택적으로 답하는 진행 상황 및 방해 부담 응답은 로컬에 저장되며, 답하지 않으면 결측값으로 남습니다.
- 실험적 로컬 교차 실험은 명시적으로 동의한 뒤에만 사용할 수 있습니다. 확인 없는 세션과 드문 확인이 있는 세션을 번갈아 배정하며, 조건에 노출되기 전에 배정을 영구 저장합니다. 자동으로 업로드하지 않으며 언제든 탈퇴할 수 있습니다.
- 공통 코어 테스트, 두 앱의 분석/테스트, Windows 릴리스 빌드, iOS 시뮬레이터 빌드를 위한 CI.

기존 `0.1.x` 버전의 설정과 세션 이벤트는 조용히 삭제되지 않고 마이그레이션됩니다. 스키마 버전 `6`은 이전의 모든 마이그레이션, 명시적 연구 참여, 세션별 배정을 유지하면서, 새 연구 세션에 실제 목표 확인 활성화 여부, 간격, 응답 시간의 스냅샷을 추가합니다. 연구용 내보내기 스키마 v2는 원본 세션 ID, 날짜, 자유 입력 텍스트뿐 아니라 절대 배정 타임스탬프도 제거합니다. 적응형 간격은 결정적이고 검토 가능한 휴리스틱이지 머신러닝 모델이 아니며, 간격을 바꾸기 전에 최소 세 번의 세션과 여섯 번의 응답을 기다립니다.

<a id="evidence-boundary"></a>

## 근거의 범위

설계는 직접적이고 서로 일치하는 연구 결과에 가장 큰 비중을 두며, 간접 추론은 명시합니다.

- 알림은 진행 중인 작업을 방해할 수 있으므로 외부 알림과 소리는 기본적으로 꺼져 있습니다.
- 짧은 휴식은 인지 수행보다 활력/피로 측면에서 더 일관된 효과를 보이므로, 확인은 선택 사항이며 수행 향상을 약속하지 않습니다.
- 사용자가 직접 작성한 실행 의도와 자기 모니터링은 복귀를 지원할 가능성이 있지만, 현대의 편향에 강건한 추정치는 초기 메타분석의 추정치보다 작습니다. 이 앱 자체와 기본값인 12~18분 간격은 무작위 배정 제품 시험에서 검증되지 않았습니다.
- 인출 연습과 간격 학습에는 더 강한 학습 근거가 있지만, 타이머만으로 인출 연습 중재가 되는 것은 아닙니다.

주장과 기능의 대응표, 한계, 평가 설계, 스키마 계약, 근거에 부합하는 최소 학습 순환은 [근거 기반](../EVIDENCE_BASE.md), [측정 계획](../MEASUREMENT_PLAN.md), [데이터 사전](../DATA_DICTIONARY.md), [로컬 교차 실험 프로토콜](../LOCAL_CROSSOVER_PROTOCOL.md), [실험적 학습 모드 명세](../LEARNING_MODE_SPEC.md)를 참조하세요.

<a id="common-questions"></a>

## 자주 묻는 질문

**강제 휴식 타이머와 어떻게 다른가요?** 목표 확인은 집중 시간을 멈추지 않습니다. 응답하거나 건너뛰거나 세션 전체의 필수적이지 않은 확인을 끌 수 있습니다. 휴식은 별도의 상태로 유지됩니다.

**산만해졌다고 보고하면 더 자주 방해하나요?** 문서화된 부담 감소 휴리스틱은 작업에서 벗어났다는 자기 보고 뒤에 방해 빈도를 높이지 않습니다. 결정적이고 검토 가능하며, 학습된 주의력 모델이 아닙니다.

**왜 알림 소리가 들리지 않나요?** 새 설치에서는 포그라운드 소리와 외부 알림이 꺼져 있습니다. 조용한 세션이 실패했다고 생각하지 말고 설정을 의식적으로 확인하세요. OS 권한과 백그라운드 동작 역시 플랫폼별 검증이 필요합니다.

**Windows에서 iPhone 앱을 설치할 수 있나요?** Dart 코드를 편집하고 테스트할 수는 있지만, 실제 iPhone 빌드/서명 단계에는 macOS의 Xcode가 필요합니다. [iOS 가이드](../../apps/ios/README.md)를 참조하세요.

**기록이 더 많이 배웠다는 증거인가요?** 아닙니다. 타이머 시간, 완료 여부, 자기 보고는 객관적인 학습 또는 생산성 결과가 아닙니다. 선택적 결과 질문에 답하지 않으면 결측 상태로 남습니다.

**실험에 꼭 참여해야 하나요?** 아닙니다. 로컬 교차 실험에는 명시적 동의가 필요하고, 탈퇴할 수 있으며, 자동 업로드도 하지 않습니다. 사용하기 전에 [프로토콜](../LOCAL_CROSSOVER_PROTOCOL.md)을 확인하세요.

<a id="develop"></a>

## 개발

현재 안정 버전 Flutter SDK와 대상 플랫폼 도구를 설치하세요. Windows 앱은 Windows 개발 호스트를, iOS 빌드는 Xcode가 설치된 macOS를 사용합니다. 아래 명령은 저장소 루트에서 시작합니다. 자세한 내용은 [Windows](../../apps/windows/README.md) 및 [iOS](../../apps/ios/README.md) 플랫폼 가이드를 참조하세요.

```powershell
cd packages\focus_core
dart pub get
dart analyze --fatal-infos
dart test

cd ..\..\apps\windows
flutter pub get
flutter analyze --fatal-infos
flutter test
flutter run -d windows
```

**첫 성공 확인:** 로컬 앱 빌드를 실행하고 목표와 복귀 행동을 입력한 뒤 세션을 시작하고 일시 정지한 다음 재개합니다. 표시되는 세션 상태가 바뀌는지 확인하세요. 이는 기본적인 로컬 사용 확인이지 잠금 화면, 절전/복귀 또는 네이티브 알림 동작의 인수 검증이 아닙니다.

`apps/ios` 안에서 동일한 분석/테스트 명령을 실행하세요. iOS 빌드에는 macOS의 Xcode가 필요하며, 서명과 실기기 알림 검증에는 Apple 개발 환경이 필요합니다.

<a id="help-make-it-easier-to-use-and-verify"></a>

## 더 쉽게 사용하고 검증할 수 있도록 돕기

범위를 명확히 한 기여를 환영합니다. 특히 접근성, 마이그레이션 안전성, 플랫폼 알림 동작, 더 명확한 목표 확인 상호작용에 대한 기여가 좋습니다.

- [CONTRIBUTING.md](../../CONTRIBUTING.md)와 변경하려는 모듈의 테스트부터 살펴보세요.
- 공통 동작은 `packages/focus_core`에, 플랫폼별 동작은 해당 앱 어댑터에 유지하세요.
- 기기 테스트에는 [DEVICE_ACCEPTANCE.md](../DEVICE_ACCEPTANCE.md)를 사용하고 하드웨어, 소프트웨어 버전, 커밋, 단계, 관찰 결과를 기록하세요.
- 실행한 검사와 실행하지 못한 검사를 모두 설명하세요.

| 개선하려는 작업 | 진입점 | 포함할 검증 |
| --- | --- | --- |
| 신호 계획 및 설정 마이그레이션 | `packages/focus_core` | 도메인 테스트, 마이그레이션 입력, 개인정보 보호/기본값 계약이 유지됨을 확인. |
| iOS 세션 UI 또는 알림 | `apps/ios/lib`, `apps/ios/test` | 분석기/위젯 테스트. 실기기 검사는 별도로 명시. |
| Windows 제어, 영속화 또는 트레이 동작 | `apps/windows/lib`, `apps/windows/test` | 관련 컨트롤러/리포지토리 테스트와 명시적인 플랫폼 증거. |
| 제품 설명 | `docs/EVIDENCE_BASE.md`, `docs/PRIVACY.md` | 실제 기본값 및 근거/주장의 범위와 일치. |

인터페이스를 변경할 때는 반복 동작, 일시 정지/재개, 확인 건너뛰기, 중단된 세션도 고려하세요. 시뮬레이터나 모의 어댑터만으로 실기기 게이트를 완료 처리하지 마세요.

큰 변경은 [issue](https://github.com/son-gladyso/random-cue-focus/issues)를 열어 논의하세요. 개인 목표, 기록 또는 연구용 내보내기를 공개 예시로 제출하지 마세요. 기여는 선택적 확인, 개인정보 보호, 구현된 휴리스틱과 입증된 이점의 구분을 유지해야 합니다.
